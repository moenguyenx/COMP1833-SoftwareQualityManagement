## 🎯 Why Black Box Testing for Healthcare Software?

Black box testing evaluates the system's operational behaviour strictly from the external interface perspective without knowledge of internal code logic. In safety-critical healthcare software, it ensures that software contracts, user safety constraints, and clinical thresholds are unconditionally respected regardless of internal implementation changes (Pressman and Maxim, 2020).

## 🔬 Technique 1: Equivalence Partitioning (EP)

### Theory & Methodology
- **Equivalence Class**: A subset of the input domain where the program is presumed to treat all elements identically.
- **Rule of Completeness**: Every input variable must be partitioned such that every possible input value belongs to exactly one partition.
- **Test Generation Principle**: Select at least one representative value from each valid partition and at least one representative value from each invalid partition.

### Worked Healthcare Example: Patient Systolic Blood Pressure (mmHg)
- **Clinical System Specification**: Systolic BP valid operational range is between `60 mmHg` (severe hypotension) and `240 mmHg` (hypertensive crisis). Inputs `< 40` or `> 300` are physiologically impossible and must be rejected as sensor faults or data entry errors.

| Partition ID | Input Domain Range | Partition Classification | Representative Test Value | Expected System Behaviour |
| :---: | :--- | :---: | :---: | :--- |
| **EP-BP-01** | `60 ≤ BP ≤ 240` | **Valid (Clinical Range)** | `120 mmHg` | Accepted; normal triage calculation initiated. |
| **EP-BP-02** | `40 ≤ BP < 60` | **Valid (Severe Hypotension)** | `52 mmHg` | Accepted; flags immediate clinical warning alert. |
| **EP-BP-03** | `240 < BP ≤ 300` | **Valid (Hypertensive Crisis)** | `265 mmHg` | Accepted; triggers priority RED triage escalation. |
| **EP-BP-04** | `BP < 40` | **Invalid (Sub-physiological)** | `25 mmHg` | Rejected; emits validation error: `"Value below minimum"`. |
| **EP-BP-05** | `BP > 300` | **Invalid (Supra-physiological)**| `350 mmHg` | Rejected; emits validation error: `"Value exceeds ceiling"`. |
| **EP-BP-06** | `Non-Numeric / Null` | **Invalid (Type Violation)** | `"High"` / `null` | Rejected; emits HTTP 400 Bad Request schema error. |

## 🔬 Technique 2: Boundary Value Analysis (BVA)

### Theory & Methodology
Decades of empirical software engineering research (Sommerville, 2020) demonstrate that developers make the vast majority of off-by-one errors at comparison boundaries (`<` vs `<=`, `>` vs `>=`). BVA explicitly probes these inflection points.

### 2-Value vs 3-Value BVA
- **2-Value BVA (Standard)**: For boundary $B$, test the boundary value itself and the value immediately outside.
- **3-Value BVA (High-Assurance / Safety-Critical)**: Tests the value immediately below the boundary ($B - \epsilon$), the value on the boundary ($B$), and the value immediately above the boundary ($B + \epsilon$).

### Worked Healthcare Example: Autoclave Operating Temperature (°C)
- **Specification**: Sterilization cycle requires chamber temperature between `121.0°C` and `134.0°C` (inclusive). Resolution is `0.1°C`.

```
         Invalid Low       │          Valid Sterilization Zone          │       Invalid High
  < 121.0°C                │         121.0°C  ───────────  134.0°C       │  > 134.0°C
 ──────────────────────────┼────────────────────────────────────────────┼──────────────────────────
                   120.9°C │ 121.0°C   121.1°C         133.9°C  134.0°C │ 134.1°C
                   (BVA-1) │ (BVA-2)   (BVA-3)         (BVA-4)  (BVA-5) │ (BVA-6)
```

| Boundary Test ID | Input Value (°C) | Boundary Under Test | Expected Result | Justification |
| :---: | :---: | :--- | :--- | :--- |
| **BVA-TEMP-01** | `120.9` | Lower Boundary ($Min - 0.1$) | **Rejected / Sub-Temp Alarm** | Verifies sterilization heater kicks in; rejects invalid cycle. |
| **BVA-TEMP-02** | `121.0` | Lower Boundary ($Min$) | **Accepted (Minimum Pass)** | Edge of valid sterilization temperature. |
| **BVA-TEMP-03** | `121.1` | Lower Boundary ($Min + 0.1$) | **Accepted (Normal Pass)** | Just inside the valid range. |
| **BVA-TEMP-04** | `133.9` | Upper Boundary ($Max - 0.1$) | **Accepted (Normal Pass)** | Just below maximum allowable operational heat. |
| **BVA-TEMP-05** | `134.0` | Upper Boundary ($Max$) | **Accepted (Maximum Pass)** | Exact upper limit before safety pressure vent activates. |
| **BVA-TEMP-06** | `134.1` | Upper Boundary ($Max + 0.1$) | **Rejected / Overheat Alarm** | Immediate emergency vent command dispatched to controller. |

## 🔬 Technique 3: Decision Table Testing

For complex clinical logic with multiple interdependent boolean conditions (e.g., Triage Priority based on Age, Heart Rate, and Consciousness), construct a Decision Table:

| Rule Conditions | Rule 1 | Rule 2 | Rule 3 | Rule 4 |
| :--- | :---: | :---: | :---: | :---: |
| **Patient Unconscious?** | **YES** | NO | NO | NO |
| **Heart Rate > 140 or < 40 bpm?** | N/A | **YES** | NO | NO |
| **Severe Trauma Symptom Present?** | N/A | N/A | **YES** | NO |
| **ACTION: Triage Classification** | **RED (Immediate)** | **ORANGE (Urgent)** | **YELLOW (Standard)** | **GREEN (Routine)** |
| **ACTION: Automated Bed Reservation** | **ICU / Resus** | **Acute Ward** | **Observation** | **Outpatient** |
