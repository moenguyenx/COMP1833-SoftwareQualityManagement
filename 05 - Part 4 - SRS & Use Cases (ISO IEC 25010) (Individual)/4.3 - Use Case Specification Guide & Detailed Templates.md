## 📐 Formal Use Case Structure (Cockburn Specification Format)

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ Use Case ID & Title : Unique reference and action verb phrase                          │
│ Primary Actor       : Initiator who triggers the interaction                           │
│ Secondary Actors    : Supporting systems, databases, or external third parties         │
│ Related SRS Link    : Cross-reference to Part 4.1 Requirement ID                       │
│ Preconditions       : Mandatory system state prior to execution                        │
│ Postconditions      : Guaranteed system state upon successful completion (Success)    │
│ Minimal Guarantee   : State guaranteed even if use case terminates abnormally          │
│ Trigger             : External or temporal event initiating the use case               │
│ Main Success Flow   : Numbered, sequential interaction steps (Happy Path)              │
│ Extensions (Flows)  : Branching conditions (exceptions, validation failures, timeouts)│
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### TOPIC 1: Performance Efficiency (Member 1)

#### Use Case 1: Real-Time Emergency Bed Allocation Under Surge (UC-PERF-01)
- **Use Case ID**: `UC-PERF-01`
- **Primary Actor**: Triage Nurse / Emergency Clinician
- **Secondary Actors**: SATZ AI Predictive Engine, Redis State Cache, PostgreSQL Cluster
- **Traceability**: Validates `SRS-PERF-01` (Time Behaviour: p99 latency ≤ 250ms)
- **Preconditions**:
  1. Clinician is authenticated via NHS Login.
  2. Patient has arrived in Emergency Department with preliminary vitals recorded.
- **Trigger**: Clinician clicks "Calculate Triage & Reserve Bed".
- **Main Success Scenario**:
  1. Clinician submits patient symptoms (Chest pain, dyspnea) and vital signs (HR: 135, BP: 165/105, SpO2: 91%).
  2. API Gateway validates payload structure against schema within 5ms.
  3. AI Predictive Triage Microservice consumes request, queries Redis for live Manchester ward bed availability, and computes Manchester Triage Score (Acuity: RED_IMMEDIATE).
  4. System locks and reserves Acute Cardiac Ward Bed (Ward 3B, Bed 04) in Redis within 45ms.
  5. System generates bedside dispatch order, commits record to PostgreSQL, and returns confirmation screen to Clinician.
  6. **End-to-End Latency Metric**: Total elapsed time from click to screen rendering is **142 milliseconds** (substantiating `SRS-PERF-01`).
- **Extensions (Alternative & Exceptional Flows)**:
  - *3a. All regional cardiac beds currently occupied*:
    - 3a1. AI optimizer queries adjacent Manchester facilities (North Manchester General / Wythenshawe).
    - 3a2. System reserves alternative bed in North Manchester and initiates automated ambulance transfer dispatch within 220ms.
  - *4a. Redis cache temporary timeout (>50ms)*:
    - 4a1. Gateway automatically fails over to read-replica database within 30ms, completing allocation within 240ms without user interruption.

#### Use Case 2: High-Frequency Sensor Ingestion & Rapid Thermal Alerting (UC-PERF-02)
- **Use Case ID**: `UC-PERF-02`
- **Primary Actor**: Autoclave IoT Pressure & Thermal Sensor
- **Secondary Actors**: Edge Gateway, Kafka Event Bus, Predictive Maintenance Service, Facility Manager
- **Traceability**: Validates `SRS-PERF-02` (Capacity: 10,000 MQTT packets/sec)
- **Preconditions**: Sensor is connected via mTLS 1.3 to hospital IoT edge gateway.
- **Trigger**: Sensor detects thermal spike (142°C in sterilization chamber, breaching 135°C threshold).
- **Main Success Scenario**:
  1. Sensor transmits telemetry packet over MQTT to Edge Gateway at 100Hz frequency.
  2. Edge Gateway normalizes packet and publishes to Kafka `facility.telemetry.urgent` topic.
  3. Stream analytics engine (Apache Flink) evaluates packet against moving average window.
  4. System flags thermal anomaly, updates TimescaleDB, and emits preventative work order.
  5. Push alert dispatched to Facility Manager's ruggedized tablet within **310ms** of physical spike.
- **Extensions**:
  - *2a. Network congestion between edge and cloud*:
    - 2a1. Edge gateway buffers telemetry locally in SQLite buffer; transmits throttled emergency alert via backup cellular 5G link within 400ms.

### TOPIC 2: Security (Member 2)

#### Use Case 1: Clinician Multi-Factor Authentication & RBAC Health Record Access (UC-SEC-01)
- **Use Case ID**: `UC-SEC-01`
- **Primary Actor**: Hospital Consultant
- **Secondary Actors**: NHS Identity Provider, OAuth2 Token Broker, Audit Logger
- **Traceability**: Validates `SRS-SEC-01` (Confidentiality & Access Control)
- **Main Success Scenario**:
  1. Consultant enters credentials and inserts NHS Smartcard / FIDO2 security key.
  2. Identity service verifies cryptographic token and issues scoped OAuth2 JWT containing claim `role: "CONSULTANT"`.
  3. Consultant requests full Electronic Patient Record (EPR).
  4. API Gateway decodes JWT, verifies authorization, retrieves decrypted record, and transmits to workstation.
  5. Immutable audit entry logged: `User [ID] accessed Patient [EPR-ID] at [Timestamp]`.

#### Use Case 2: Third-Party Provider Restricted Access & Tokenized Routing (UC-SEC-02)
- **Use Case ID**: `UC-SEC-02`
- **Primary Actor**: Contracted Equipment Maintenance Engineer
- **Secondary Actors**: Field Service Portal, Data Masking Service
- **Traceability**: Validates `SRS-SEC-01` & `SRS-SEC-02` (Caldicott Principle 2)
- **Main Success Scenario**:
  1. Contractor logs in with provider role credentials.
  2. Contractor opens assigned work order for Autoclave 04 in Surgical Ward 2.
  3. Data Masking Service intercepts data stream: strips all patient identifiers, names, and medical notes; renders only asset metadata, room number, and maintenance diagnostic history.
  4. Contractor completes repair and cryptographically signs work order completion.

### TOPIC 3: Usability (Member 3)

#### Use Case 1: Novice Clinician Rapid Bed Dispatch with Inline Error Recovery (UC-USAB-01)
- **Use Case ID**: `UC-USAB-01`
- **Primary Actor**: Newly Recruited Ward Nurse (Zero Prior Training)
- **Traceability**: Validates `SRS-USAB-01` (Learnability & Error Protection)
- **Main Success Scenario**:
  1. Nurse logs in and encounters context-sensitive onboarding overlay highlighting "Quick Triage".
  2. Nurse enters patient vitals. Inadvertently types `400` into `Heart Rate` field.
  3. Form immediately flags field with soft amber highlight and plain-English modal: *"Heart rate 400 exceeds physiological limit. Did you mean 40 or 140?"*
  4. Nurse corrects value to `140`. System enables one-click "Confirm Allocation" button.
  5. Bed confirmed in 1 minute 45 seconds total task time without supervisor intervention.

#### Use Case 2: Visually Impaired Patient Booking Appointment via Accessible Portal (UC-USAB-02)
- **Use Case ID**: `UC-USAB-02`
- **Primary Actor**: Elderly Patient with Macular Degeneration (Using Screen Reader)
- **Traceability**: Validates `SRS-USAB-02` (WCAG 2.1 AA Accessibility)
- **Main Success Scenario**:
  1. Patient navigates to MHE Self-Service portal using NVDA / JAWS screen reader.
  2. Screen reader announces semantic landmarks and high-contrast toggle.
  3. Patient tabs through accessible calendar widget; dates announced clearly with availability context.
  4. Patient confirms appointment and receives SMS booking code.
